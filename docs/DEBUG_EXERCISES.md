# バグ改修演習

わざとバグを仕込んで、**症状から原因までを自力でたどる**演習です。
先に [READING_GUIDE.md](./READING_GUIDE.md) を読んでおいてください。

> このページに解答は書いていません。
> `exercises/bugs.mjs` には答えが書いてあるので、**取り組んでいる間は開かないでください。**

---

## 使い方

```bash
npm run bug -- list          # 問題の一覧
npm run bug -- apply 03      # 3番を仕込む
npm run bug -- random        # ランダムに1つ仕込む（番号は表示されない）
npm run bug -- status        # いま仕込まれている番号（答え合わせ用）
npm run bug -- reset         # すべて元に戻す
```

仕込んだら `npm run dev` で動かして症状を確認してください。

### 進め方（1問あたり15〜30分が目安）

1. **症状を再現する** — 書いてある手順どおりに操作して、自分の目で確認する
2. **どの層の話かを決める** — 表示 / キャッシュ / 変換 / 通信 / 状態の持ち主、のどれか
3. **原因のファイルと行を特定する** — 直す前に、まず場所を言えるようにする
4. **なぜそうなるかを説明する** — 「ここが違うから、こうなる」を1文で
5. **直す**
6. **`npm run test` を実行する**
7. **`npm run bug -- reset` で元に戻す**

**4 を飛ばさないでください。** 直せても説明できなければ、次に同じバグを作ります。

### テストについて

一部のバグは `npm run test` を実行すると自動で見つかります。
**一部は見つかりません。** どちらだったかを毎回記録しておいてください。
「テストが無い場所はどこか」を知ることも、この演習の目的のひとつです。

**再現**
ログイン → 商品一覧 → 商品をクリック → カートに追加 → ヘッダを見る

<details><summary>ヒント1</summary>

</details>

## 仕上げの課題

すべて直し終えたら、次をやってください。

1. **テストで見つからなかったバグを洗い出す**
   どれがテストで検出され、どれが検出されなかったかを一覧にする。

2. **検出されなかったバグのうち1つに、テストを書く**
   既存のテスト（`src/features/add-to-cart/ui/AddToCartButton.test.tsx` など）を真似してください。
   そのテストを書いた状態で `npm run bug -- apply <番号>` を実行し、
   **テストが落ちること**を確認してから reset してください。

3. **「なぜこのバグは起きたのか」を設計の言葉で説明する**
   たとえば #04 なら「Server State を Client State にコピーしたから」。
   12個すべてについて1文で書けたら、この教材は卒業です。
